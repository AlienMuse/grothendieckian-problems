# Problem 34 · A second kernel

**Kind.** Formalization problem, entry level. Thesis 6 ([A chain of non-implications](../THESES.md#thesis-6)).

**Source.** *GM-Omega-Infinity: Topos-Native Intelligence* [S02], Open Problem 13.15.D, p. 3135. DOI [10.5281/zenodo.23538544](https://doi.org/10.5281/zenodo.23538544).

**Status in the source.** OPEN / D.

**Statement.** “Establish whether an independent type-checker covers the features used by the 13.11 and 13.13 developments, and if so make REPLAYED require two kernels rather than two machines.” Independent checkers for Lean 4 now exist [Car24; nanoda]; the problem is to elaborate the Lean declarations of [S02, Table 13.15.1] at a pinned toolchain and replay them under Lean’s kernel and under an independent checker.

**What the source establishes.** In the release no declaration was elaborated, and the source says of its replay status: “The present definition of REPLAYED is weaker than the name suggests, and this is stated rather than hidden.”

**Proposed by.** [S02].

**Background.** [BW05]; [MU21]; [Car24]; [nanoda].

**Solved when.** The declarations elaborated at a pinned toolchain and replayed by two independent kernels, with a report of the features used and of any declaration that one kernel rejects.

**Literature check (28 October 2026).** Independent Lean 4 checkers were found [Car24; nanoda]; the Lean 4 repository contains a replay checker and an export format (src/LeanChecker.lean, src/LeanExport; GitHub code search, leanprover/lean4). No replay of these declarations was found.

**Discussion.** [Issue 34](https://github.com/AlienMuse/grothendieckian-problems/issues/34). Solutions, partial results, counterexamples to the problem as stated and reports that it is already solved are all welcome; see [CONTRIBUTING](../CONTRIBUTING.md).
