# Problem 12 · Deterministic identity across implementations

**Kind.** Machine problem, entry level. Thesis 6 ([A chain of non-implications](../THESES.md#thesis-6)).

**Source.** *GAI-MUA: The Grothendieckian Machine* [S01], Vol. V, Proposition 2.2, p. 11920, and Proposition 3.2, p. 11927. DOI [10.5281/zenodo.23480696](https://doi.org/10.5281/zenodo.23480696).

**Status in the source.** D/O.

**Statement.** Build two independent implementations of the canonical serialization and replay profile of [S01, Vol. V] and show that they agree: identical canonical bytes and identifiers for the same artifacts (Proposition 2.2), and identical kernel judgments under identical inputs and environments (Proposition 3.2).

**What the source establishes.** Proposition 2.2 is “an interoperability obligation to be tested by cross-language fixtures.” For replay, “A disagreement is a first-class incident”, and “The system does not choose the favorable result by majority vote.” No second implementation exists.

**Proposed by.** [S01].

**Background.** [LZ22]; [Nec97].

**Solved when.** Two implementations in different languages by different authors, and a published fixture suite (Unicode normalisation, exact numbers, ordered and unordered collections, extension fields) on which they agree byte for byte, with every disagreement found during development recorded as an incident.

**Literature check (28 October 2026).** Reproducible-builds practice [LZ22] addresses the same property for software artifacts; no implementation of this profile was found.

**Discussion.** [Issue 12](https://github.com/AlienMuse/grothendieckian-problems/issues/12). Solutions, partial results, counterexamples to the problem as stated and reports that it is already solved are all welcome; see [CONTRIBUTING](../CONTRIBUTING.md).
